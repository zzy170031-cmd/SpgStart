  - `syncRankings()` 分步写状态，可能造成半更新

### C. 测试运维

- 这刀提升了第三页的可测性和可观测性。
- 当前仍需重点警惕：
  - 重复函数带来的行为漂移
  - 半更新状态带来的页面真相不一致
  - 需要固定 smoke check 验证桌面端启动与三页链路

## 总设计师拍板

### 不优先做的事

- 暂不把“决策卡动作层”作为下一刀第一优先级。
- 暂不先处理 `/login` 回退出口。
- 暂不把 `metadata_json` 扩成数据库结构重构。

### 下一刀唯一优先级

把第三页收敛成“单次快照渲染”，先解决同一屏里数据不同步、不同口径、不同真相的问题。

### 下一刀固定范围

1. 清掉 `workbench_v3.js` 里重复的：
   - `renderVideoPanel`
   - `renderRightPanels`
   - `refreshDashboard`

2. 把第三页刷新改成：
   - 拿到完整快照后一次性落状态
   - 不允许 `gameRankings / eventRankings / contentRankings` 分步写入导致半新半旧

3. 统一 Provider 展示口径：
   - 只认一套来源
   - 不再让 `providers` 和 `budgets` 在前端互相 fallback 出两套答案

4. 补两条验证：
   - `overview / rankings / content` 的 `trust` 口径一致
   - 任一步抓取失败时，页面保持上一次完整快照或明确失败态，不出现半更新

## 明天继续的建议顺序
