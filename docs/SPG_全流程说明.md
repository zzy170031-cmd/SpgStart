# SPG 全流程说明

## 1. 项目定位

SPG 是一个面向 `SLG 赛道短视频选题` 的桌面工作台。

当前第一阶段目标是：

- 通过桌面启动器进入系统
- 完成 `本地用户确认 -> API 配置测试 -> 主系统`
- 基于多 API 组合，持续抓取并分析抖音上的 SLG 热点内容
- 产出：
  - 游戏热度
  - 热门视频拆解
  - 创作指导
  - 选题池

## 1.1 工程核心协作机制

从当前版本开始，SPG 主工程的研发、复盘和上线前检查，固定采用 `四代理协作机制`，它属于工程核心步骤的一部分，不再按单轮任务临时变更。

固定角色如下：

- `代理 A / Maxwell`：产品经理
- `代理 B / Dirac`：软件工程师
- `代理 C / Parfit`：产品 UI 与产品测试运维
- `代理 D / Wegener`：总设计师

固定职责如下：

### 代理 A / Maxwell

职责：

- 从产品实现角度审查当前方案
- 从用户体验与运营可用性角度提出建设意见
- 对功能是否真的能被使用、能否降低理解成本负责

### 代理 B / Dirac

职责：

- 用 Rust 主线承接产品实现
- 从架构、运行链路、数据链路、稳定性角度提出技术建议
- 对“能不能真正跑起来、能不能稳定落地”负责

### 代理 C / Parfit

职责：

- 从 UI 呈现、页面布局、交互细节角度提出意见
- 从产品测试与运维落地角度验证是否能顺畅操作、是否方便排障
- 对“是否看得清、用得顺、测得通”负责

### 代理 D / Wegener

职责：

- 统筹 A / B / C 三方意见
- 从产品、设计、技术、测试全流程角度做总判断
- 在每一轮更新后做两轮质询与最终决策收口

固定工作流如下：

1. 每次主线更新后，A / B / C 先各自独立检查。
2. D 汇总三人的结论后，分别对 A / B / C 做两轮质询。
3. 质询结束后，D 归纳总结，并给出最终决策方案。
4. 若本轮没有真实问题，可以明确写“无新增问题”，不强行挑刺。
5. 所有意见必须以“可落地、可执行、可验证”为先，不以形式化挑错为目标。

复用约束如下：

- 后续默认只允许使用这四个固定角色，不再临时换一组新角色名。
- 若会话层代理实例失效，必须按 `同名 / 同职责 / 同顺序` 立刻重建后再继续，不得借机改动分工。
- 工程文档、复盘结论、实现建议，都以这四个角色体系为准。

## 2. 当前桌面流程

### 第 1 页：桌面入口确认

作用：

- 确认当前本机用户
- 确认当前设备已通过本地身份校验
- 决定是否进入主系统或回到 API 配置页

关键规则：

- 只有确认过本地用户，才能进入第 2 页或直接进入主系统
- 退出登录后，需要重新确认

### 第 2 页：API 配置测试页

作用：

- 配置必需 API
- 测试 API 是否真正可用
- 只有必需 API 全部通过后，主系统才解锁

当前必需 API：

- Doubao
- Serper
- Exa
- Tavily
- Firecrawl

关键规则：

- 任一必需 API 变更后，放行状态失效
- `保存配置` 和 `测试 API` 都是真实链路，不是演示按钮

### 第 3 页：主系统页面

主系统采用 `三列主控台` 布局：

- 左列：游戏搜索区、API 调用实况区
- 中列：赛道游戏可视化排名区、抖音视频拆解区
- 右列：热门视频拆解区、创作指导区

## 3. 当前 UI 方向

已经锁定的设计语言：

- 主配色：白 / 黑 / 灰
- 风格：克制、简洁、细线条、高留白
- 不再使用花哨深空面板和大面积渐变
- 页面优先强调：
  - 操作
  - 层级
  - 对齐
  - 信息清晰度

当前这版 UI 已被确认保留，后续不再大改整体视觉方向。

## 4. 技术实现结构

项目核心全部基于 `Rust`，不是 Python 或 Node 后端。

### `crates/spg-core`

职责：

- 游戏实体识别
- 别名识别
- 资产加载
- SQLite 底层入库
- 数据规范化

### `crates/spg-web`

职责：

- 本地 Web 服务
- 页面路由
- 主系统接口
- 调度器
- API 编排
- 工作台数据聚合

### `crates/spg-desktop`

职责：

- Windows 桌面启动器
- 静默启动
- 不弹终端
- 拉起本地服务并承载桌面窗口

## 6. 当前真实运行流程

每轮工作流固定为：

1. 用 Doubao 规划本轮查询
2. 用 Serper 做主发现
3. 用 Exa 做长尾补充
4. 过滤为抖音候选
5. 用 Firecrawl 抓取短名单正文
6. 用 Tavily 做热点验证
7. 用 Doubao 输出结构化拆解
8. 入库并生成：
   - 内容榜
   - 游戏榜
   - 事件榜
   - 视频拆解
   - 创作建议
   - 选题池条目
