# SPG 全流程说明

## 1. 项目定位

SPG 是一个面向 Douyin `SLG` 赛道的本地桌面工作台。当前主线目标是形成以下闭环：

1. 本地身份确认
2. Provider 配置与真实可用性验证
3. 进入 Workbench 主系统
4. 完成游戏搜索、热点发现、内容拆解、创作指导、选题池沉淀

它不是通用爬虫平台，而是围绕 `SLG` 内容洞察与创作决策的产品化工作台。

## 2. 当前治理基线

从当前版本开始，SPG 的现行治理规则固定接入 `five-agent-governance`，不再把旧四代理文档当作默认规则。

### 2.1 五代理链路

- `Maxwell`
  负责需求理解、目标澄清、边界收紧、成功标准确认
- `Dirac`
  负责实现路径、模块边界、接口与可行性判断
- `Parfit`
  负责 UI/UX、测试、运维、一致性和维护风险审查
- `Wegener`
  负责整合前三者，并完成两轮质询与两轮自审
- `Popper`
  负责三轮反问和最终五态裁决

### 2.2 固定检查点

现行治理默认覆盖以下检查点：

- 需求冻结前
- 方案冻结前
- 实现前
- 合并前
- 发布前

### 2.3 五态裁决

`Popper` 的最终裁决只能是以下之一：

- `PASS`
- `PATCH`
- `WAIT`
- `NO`
- `ESCALATE`

没有 `Popper` 裁决，不进入下一个正式检查点。

## 3. 当前桌面流程

### 3.1 第一页：桌面入口确认

作用：

- 确认当前本地用户
- 确认设备已通过本地身份校验
- 决定是进入主系统还是返回 Provider 配置页

### 3.2 第二页：Provider 配置测试

作用：

- 配置必需 Provider
- 测试 Provider 是否真实可用
- 只有必需 Provider 全部通过后，主系统才解锁

当前必需 Provider：

- Doubao
- Serper
- Exa
- Tavily
- Firecrawl

### 3.3 第三页：Workbench 主系统

当前主界面采用三列工作台布局：

- 左列：游戏搜索、筛选、Provider 状态和预算感知
- 中列：赛道与游戏热点可视化
- 右列：内容拆解、创作指导、选题池沉淀

## 4. 当前 UI 方向

已确认的设计语言：

- 主色偏白、黑、灰
- 简洁、克制、高留白
- 以信息层级、对齐和可执行性优先
- 不再回到大面积花哨渐变和概念化装饰

这意味着当前 UI 主方向以“工作台可读性和可执行性”为先，而不是视觉炫技。

## 5. 技术结构

### 5.1 `crates/spg-core`

负责：

- 游戏实体识别
- 别名识别
- 规则处理
- SQLite 持久化
- 核心输入与分析链路

### 5.2 `crates/spg-web`

负责：

- 本地 Web 服务
- 页面路由
- Provider 配置与测试
- Workbench 调度
- 主系统 API

### 5.3 `crates/spg-desktop`

负责：

- Windows 桌面壳
- 本地服务引导
- 托盘
- 窗口生命周期

## 6. 数据与 Provider 方向

当前平台固定聚焦：

- `douyin`

当前正式监控的 7 个游戏：

- 率土之滨
- 三国群英传策定九州
- 三国谋定天下
- 无尽冬日
- 三国冰河时代
- 天下归心
- 九牧之野

当前默认分析模型：

- `doubao-seed-2-0-code-preview-260215`
